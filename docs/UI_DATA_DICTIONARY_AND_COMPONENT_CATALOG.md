# NyayaVani (न्यायवाणी) — Frontend UI Data Dictionary & Component Catalog

> **Audience:** Frontend Engineers, UI/UX Designers, and Mobile/Web Developers building interfaces for NyayaVani.  
> **Purpose:** Comprehensive specification of every field returned by the backend API, how it is derived, why it exists, and how to selectively present it to an ordinary citizen versus a legal professional or hackathon judge.

---

## 1. The UX Problem & Design Philosophy

### The Problem
Currently, the backend outputs a comprehensive payload containing everything from conversational guidance down to raw cryptographic evidence hashes and API timing benchmarks. When all fields are dumped into a single chat bubble:
1. **Cognitive Overload:** An anxious street vendor or rural citizen is confronted with dense statutes, penalties, and technical jargon before hearing what they actually need to do.
2. **Cryptographic Hashes in the Open:** Displaying raw 64-character SHA-256 strings (`c1fb56c5f598...`) in plain chat confuses ordinary users who do not know what Bharatiya Sakshya Adhiniyam (BSA) Section 63 means.
3. **Scroll Fatigue & Displaced Audio:** The voice player gets pushed up or buried beneath walls of text, forcing the user to scroll back and forth to listen to the audio rights shield.

### Design Hierarchy
To solve this, divide every response into three distinct layers:
* **Layer 1: Citizen View (Always Visible, Compact):** Audio player, simple 2-sentence explanation in plain words, and clear immediate next step.
* **Layer 2: Legal Proof Drawer (Expandable / On-Demand):** The formal Section 173 FIR / TVC representation document, exact legal sections, and download button.
* **Layer 3: Hackathon / Audit Telemetry (Hidden by Default):** BSA electronic hashes, API latency, model versions, and payload sizes accessible via a small "Inspector" toggle.

```
+-------------------------------------------------------------+
| LAYER 1: CITIZEN VIEW (Default in Chat)                     |
|  [🔊 Voice Audio Player - Loudspeaker Shield]               |
|  "In Plain Words: What is happening right now"              |
|  "What You Should Do: Immediate practical step"             |
+-------------------------------------------------------------+
| LAYER 2: LEGAL EVIDENCE & FILINGS (Collapsible / Drawer)     |
|  ▸ View Governing Legal Sections (Act, Section, Rule)       |
|  ▸ View & Copy Generated Legal Notice / Zero FIR Draft      |
|  ▸ Download BSA Sec 63 Electronic Record Digest (Review Draft)|
+-------------------------------------------------------------+
| LAYER 3: DEVELOPER / JUDGE TELEMETRY (Collapsed Tray)       |
|  ▸ Live API Latency | STT/TTS Models | Audio Payload Size   |
+-------------------------------------------------------------+
```

## 2. API Endpoints Overview

NyayaVani exposes two primary endpoints for conversational legal intelligence:

| Endpoint | Method | Input Type | Description |
| :--- | :---: | :--- | :--- |
| `/api/chat` | `POST` | `application/json` | Primary chat endpoint for text input (vernacular or English). |
| `/api/chat/voice` | `POST` | `multipart/form-data` | Voice endpoint accepting browser audio recordings (WAV/WebM). |

## 4. Deep-Dive: The `legality_verdict` Object

The `legality_verdict` is the brain of NyayaVani. It translates dense legal graph traversals into citizen-friendly instructions:

```json
{
  "is_lawful": false,
  "citizen_fault": false,
  "status": "UNLAWFUL_ACT_BY_AUTHORITY",
  "follow_up_required": false,
  "follow_up_question": null,
  "follow_up_reason": null,
  "plain_explanation": "Under Indian law, police or municipal staff cannot randomly evict you or demand daily bribes. You are protected until an official Town Vending Committee survey is completed.",
  "what_to_do": "Show your PM SVANidhi receipt or vending certificate. Do not pay cash without an official government receipt. Inform them you are protected under Section 3(3).",
  "legal_source_statutes": [
    {
      "act": "The Street Vendors (Protection of Livelihood) Act, 2014",
      "section": "Section 3(3)",
      "rule": "Absolute bar on eviction or relocation pending Town Vending Committee survey"
    },
    {
      "act": "Bharatiya Nyaya Sanhita (BNS), 2023",
      "section": "Section 308",
      "rule": "Criminal extortion for demanding unauthorized money under coercion"
    }
  ],
  "verdict_summary": "ILLEGAL ACTION. Municipal staff have no legal authority to evict you without a TVC survey.",
  "citizen_standing": "You are 100% statutorily protected and have the legal right to remain at this vending location.",
  "violator_liability": "Cognizable criminal offense under BNS Section 308 (Extortion) punishable with up to 7 years imprisonment."
}
```

### Sub-field Definitions:

| Key | Type | Meaning | How the UI Should Treat It |
| :--- | :---: | :--- | :--- |
| `follow_up_required` | `boolean` | `true` if facts are missing (e.g. "Police stopped me" without explaining why). | **Priority UI trigger.** If `true`, render an interactive question box prompting the user to clarify. |
| `follow_up_question` | `string` | The plain-English question the user must answer before an official verdict can be issued. | Display as large primary prompt with reply suggestion chips. |
| `plain_explanation` | `string` | Explainable, non-technical explanation of what is happening under the law. | **Main card body.** Written so an illiterate or non-technical vendor understands immediately. |
| `what_to_do` | `string` | Immediate, concrete action items (e.g. "Do not pay cash", "Demand seizure memo"). | **Action box.** Highlighted in a distinct visual callout. |
| `legal_source_statutes` | `array` | Structured list of `{ act, section, rule }` objects. | Clean badges/chips. Clicking one reveals the operative legal rule. |
| `citizen_fault` | `boolean` | `true` if citizen committed a violation (spoiled food, drunk driving, unauthorized permanent building). | Render warning banner (`⚠️ CITIZEN NON-COMPLIANCE`). |
| `is_lawful` | `boolean` | `true` if authority action is lawful; `false` if opponent is acting illegally. | Drives card theme color (Green = Rights Protected, Orange = Lawful Authority, Amber = Ambiguous). |
| `violator_liability` | `string` | Penalties or fines faced by the wrongdoer or citizen. | Secondary legal detail. Keep collapsed or in detailed breakdown. |
| `citizen_standing` | `string` | Formal legal status of the citizen under Indian law. | Secondary legal detail. |

## 6. Where Telemetry and Evidence Should Go

| Data Point | What it Looks Like | Where it SHOULD Go in the UI |
| :--- | :--- | :--- |
| **BSA SHA-256 Hash** | `c1fb56c5f598bb7988ac...` | Inside a modal: "View Section 63 Evidence Certificate" or a discreet badge `[🔒 Electronic Evidence Timestamped]`. Never raw text. |
| **Formal Document** | Multi-paragraph legal notice | Inside a tab or slide-over drawer: `[📄 Open Legal Notice]`. Include a one-click "Copy Notice" or "Share on WhatsApp" button. |
| **API Latency** | `elapsed_seconds: 2.119s` | Inside a subtle collapsed developer footer: `● Gnani Live API (2.1s)`. |
| **TTS Model & Bytes** | `timbre-v3.0 | 350 KB` | Collapsed in developer telemetry tray. |
| **PRISMA STT ID** | `req_98af21...` | Collapsed in developer telemetry tray. |

## 7. Sample Integration Code (JavaScript / React / Vue)

```javascript
/**
 * Transforms raw NyayaVani backend response into clean, tier-separated UI state.
 */
export function parseNyayaVaniResponse(data) {
  const verdict = data.legality_verdict || {};

  return {
    // 1. Citizen Core Tier (Always Visible)
    isFollowUp: Boolean(verdict.follow_up_required),
    followUpQuestion: verdict.follow_up_question || null,
    isCitizenFault: Boolean(verdict.citizen_fault),
    plainExplanation: verdict.plain_explanation || verdict.verdict_summary || "Legal analysis complete.",
    whatToDo: verdict.what_to_do || verdict.citizen_standing || "Follow statutory directions.",
    audioUrl: data.audio_url,
    spokenCaption: data.spoken_text,

    // 2. Legal Backing Tier (Collapsed Accordion / Modal)
    statutes: verdict.legal_source_statutes || [],
    formalDocument: data.formal_document,
    actionRoadmap: data.action_steps || [],

    // 3. Evidence & Compliance Tier (Modal Dialog)
    bsaEvidence: {
      sha256: data.sha256,
      certificate: data.certificate,
      timestamp: data.timestamp
    },

    // 4. Developer / Judge Telemetry Tier (Collapsed Tray)
    telemetry: {
      apiMode: data.api_mode,
      category: data.category,
      tier: data.tier,
      ttsElapsed: data.tts_telemetry?.elapsed_seconds,
      ttsVoice: data.tts_telemetry?.voice,
      sttLatency: data.stt_telemetry?.processing_time
    }
  };
}
```

## 8. Summary Checklist for Frontend Implementation

1. [ ] **Keep Audio at the Top:** Place the `<audio>` player at the top of the assistant card so it is immediately playable without scrolling.
2. [ ] **Show Plain Words First:** Highlight `plain_explanation` and `what_to_do` in large, legible typography.
3. [ ] **Hide Raw Hashes:** Move `sha256` and `certificate` into a "View BSA 2023 Certificate" modal.
4. [ ] **Drawer for Legal Filings:** Move `formal_document` into a collapsible drawer or popover with a "Copy Document" button.
5. [ ] **Interactive Follow-up Chips:** When `follow_up_required` is `true`, show quick-reply buttons for common answers.
6. [ ] **Collapsed Dev Strip:** Keep latency, byte size, and model names in a discreet bottom bar.
